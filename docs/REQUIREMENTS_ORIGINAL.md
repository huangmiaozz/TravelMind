TravelMind 智能旅行规划系统——项目需求说明

我准备正式开发一个名为 TravelMind 的智能旅行规划系统，希望你作为我的项目开发助手，后续协助我完成需求分析、系统设计、数据库设计、后端、前端、数据采集、算法以及测试等工作。

请注意：不要一开始就直接写大量代码。我们要按照真实的软件工程项目流程，从需求和架构开始，逐步完成开发。

⸻

一、项目核心目标

我想开发一个能够为用户规划完整旅行方案的系统。

用户只需要输入：

* 出发地
* 目的地
* 旅行日期
* 旅行天数
* 人数
* 总预算
* 兴趣偏好
* 交通偏好
* 住宿偏好
* 每天可接受的出行时间
* 每天最大步行距离
* 其他个性化要求

系统自动从多个公开数据源获取旅行相关信息，并综合考虑：

* 景点
* 景点开放时间
* 景点门票
* 景点位置
* 景点推荐游玩时间
* 酒店
* 酒店价格
* 酒店位置
* 航班
* 高铁/火车
* 公共交通
* 驾车
* 步行
* 天气
* 节假日
* 活动
* 餐饮
* 用户兴趣
* 预算
* 时间限制
* 景点之间的空间距离

然后通过旅行规划算法自动生成一个或多个完整旅行方案。

⸻

二、项目的核心理念

这个项目不是简单的：

“AI 帮用户写一篇旅游攻略。”

而是：

基于真实数据 + 用户约束 + 多目标优化，自动生成可执行的旅行计划。

例如用户输入：

出发地：福州
目的地：北京
旅行时间：5天
人数：2人
预算：8000元
兴趣：
历史文化 90%
美食 70%
自然风光 50%
购物 20%
要求：
每天 08:00～22:00
每天最多步行 15km
优先公共交通
不要安排得太紧

系统应该自动计算：

景点选择
↓
景点组合
↓
景点游玩顺序
↓
景点开放时间
↓
景点之间交通
↓
每天时间安排
↓
酒店选择
↓
交通方式
↓
费用
↓
天气
↓
综合评分

最后生成：

方案 A：综合最优
方案 B：最省钱
方案 C：最舒适
方案 D：兴趣匹配度最高

路线合理程度
兴趣匹配度
天气适应性
舒适度

可以建立综合评分模型：

Score =
w1 * Interest
+
w2 * Time
+
w3 * Cost
+
w4 * Route
+
w5 * Weather
+
w6 * Comfort

其中权重应该根据用户偏好动态调整。

Cost 40%
Time 20%
Comfort 10%
Interest 30%

舒适型

Cost 10%
Time 30%
Comfort 40%
Interest 20%

兴趣优先

Route 15%

十二、AI 的作用

AI 不应该负责整个旅行规划。

希望采用：

AI
↓
理解自然语言需求
↓
转换成结构化参数
↓
交给 Planner
↓
Planner 计算结果
↓
AI 解释结果

例如用户说：

“我第一次去北京，不喜欢走太多路，喜欢历史和拍照，预算一个人4000左右。”

AI 转换成：

{
  "people": 2,
  "budget": 8000,
  "preferences": {
    "history": 0.9,
    "photography": 0.8
  },
  "constraints": {
    "max_walk_distance": 8
  }
}

然后 Planner 负责真正计算。

这样可以避免让 AI 自己编造价格、时间和路线。

二十、非常重要的开发原则

请始终遵守以下原则：

1. 不要假数据冒充真实数据

如果 API 暂时没有数据，可以使用 Mock，但必须明确标记为：

Mock Data

不能让我误以为是真实数据。

2. 不要假设 API 一定存在

涉及第三方 API 时，请先确认当前 API 的实际能力、限制和调用方式。

3. 不要把 AI 当作计算器

费用、距离、时间、路线等应该由程序计算。

4. 爬虫必须考虑合法性和网站规则

优先官方公开数据。

不要把绕过验证码、登录限制、签名验证、反爬机制作为项目核心。

5. 数据必须可追溯

重要数据记录：

source
source_url
updated_at
crawl_time
confidence

6. 优先完成 MVP

不要因为未来功能而提前把系统设计得极其复杂。
