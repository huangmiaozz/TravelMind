# 外部 API 可行性验证

> Phase 0 技术验证的产出。**不基于假设** —— 所有结论都来自实际调用。
>
> 验证日期：2026-09-18 ｜ 验证方式：`backend/scripts/probe_amap.py`（可随时重跑）

## 结论

高德地图 Web 服务 API 的 **8 个接口全部可用**，包括**公交路径规划**。

需求 11.3「优先考虑公共交通和低疲劳路线」**可以实现**，不需要换数据源。

## 验证结果

探测起终点固定为「故宫 → 中国国家博物馆」（`116.3972,39.9163` → `116.4074,39.9042`），
以便结果可复现。

| 接口 | 端点 | 耗时 | 返回内容 |
|---|---|---|---|
| 地理编码 | `/v3/geocode/geo` | 160 ms | 匹配 2 条 |
| 逆地理编码 | `/v3/geocode/regeo` | 145 ms | 准确识别为「故宫博物院」 |
| 关键字搜索 | `/v3/place/text` | 251 ms | `count=519` |
| 驾车路径 | `/v3/direction/driving` | 127 ms | 3961 m / 1191 s / 8 段 |
| 步行路径 | `/v3/direction/walking` | 116 ms | 2316 m / 1853 s / 18 段 |
| 公交路径 | `/v3/direction/transit/integrated` | 240 ms | 2592 s / ¥2.0 / 步行 1348 m / 换乘 2 段 |
| 骑行路径 | `/v4/direction/bicycling` | 157 ms | 2341 m / 562 s / 14 段 |
| 距离测量 | `/v3/distance` | 125 ms | **1 对多批量**，2 条 / 3890 m / 1168 s |

全部耗时在 **110–260 ms** 之间。

## 关键发现

### 1. 端点名陷阱：`integrated` 不是 `integration`

公交路径的正确端点是：

```text
/v3/direction/transit/integrated      ← 过去式
```

写成 `integration` 会返回 **`10002 SERVICE_NOT_AVAILABLE`** —— 这个错误码看起来像
「账号未开通该服务」，极具误导性，会让人白白去查控制台权限。

**教训**：`SERVICE_NOT_AVAILABLE` 不等于权限问题。排查第三方 API 失败时，
先核对端点拼写与文档原文，再看配额与权限。

### 2. 公交接口的 `cost` 是票价，不是时间

`route.transits[]` 的字段语义：

| 字段 | 含义 | 单位 |
|---|---|---|
| `duration` | 换乘方案预期时间 | 秒 |
| `cost` | 此换乘方案**价格** | 元 |
| `walking_distance` | 方案总步行距离 | 米 |
| `segments` | 换乘路段列表 | — |
| `nightflag` | 是否夜班车 | — |

`segments[].walking` 与 `segments[].bus.buslines[]` 里还有每段公交的线路名、上下车站、
首末班时间、途经站数 —— 足够支撑「少走路」「不乘地铁」这类偏好。

### 3. 距离测量支持 1 对多批量

`/v3/distance` 的 `origins` 参数**支持最多 100 个坐标对**（`|` 分隔），`destination` 单个。

这意味着规划器可以**一次请求**算出「从当前景点到其余所有候选点」的距离，
而不是逐对调用 N 次。对行程优化的性能影响很大。

`type` 参数：`0` 直线 / `1` 驾车 / `3` 步行。

> 注意 `type=1` 会考虑实时路况，同一对起终点在不同时间返回可能不同
> （实测 3890 m，而 `/direction/driving` 同一对坐标返回 3961 m）。

### 4. 公交的策略参数直接对应产品需求

`/v3/direction/transit/integrated` 的 `strategy` 参数：

| 值 | 策略 |
|---|---|
| 0 | 最快捷 |
| 1 | 最经济 |
| 2 | 最少换乘 |
| 3 | **最少步行** |
| 5 | 不乘地铁 |

这正好对应需求 11.3 的「低疲劳路线」，以及未来「最省钱」方案的公交取向。

### 5. POI 搜索能给出开放时间，但是自然语言

`/v3/place/text` 加 `extensions=all` 后，`biz_ext.opentime2` 提供开放时间原文：

```text
故宫  旺季4月1日至10月31日 周二至周日 08:30-17:00 16:00停止检票，
      淡季11月1日至3月31日 周二至周日 08:30-16:30 15:30停止检票，
      周一全天关闭，节假日营业时间以官方通知为准
```

注意 `biz_ext.open_time` 是**空数组** —— 结构化字段没有数据，有用的信息全在
`opentime2` 这段中文里。三个实测景点的写法各不相同（空格有无、分隔符差异、
旺季淡季、全周开放），因此需要一层解析：`backend/app/services/opening_hours.py`。

`opentime2` 自己也声明了不确定性（"节假日营业时间以官方通知为准"），
所以解析结果不给满分 confidence，原文一并入库供人工核对。

## 对设计的影响

**交通模型**：四种方式（驾车 / 步行 / 骑行 / 公交）都有可用的距离与时间，
规划器可以按用户交通偏好选择对应接口，不需要任何估算回退。

**性能**：单次调用约 120–260 ms。一个 5 天行程若有约 20 段交通，串行约 3–5 秒；
若用 `/v3/distance` 批量查询还可以进一步压缩。

**「优先公共交通」**：可用，且能细分为最少步行 / 最少换乘 / 最经济。

## 待确认

- **各项配额与 QPS** —— 官方文档只给出查询入口，实际额度需在
  [高德控制台](https://console.amap.com/) 查看。这决定了规划请求里能并行发起多少调用。
- **跨城公交** —— 本次只验证了同城（`cityd` 未触发）。跨城场景需要单独验证。
- **`/v3/distance` 的 `type=1` 时间抖动** —— 因含实时路况，需确认是否要缓存。

```powershell
cd backend
python -m scripts.probe_amap
```
